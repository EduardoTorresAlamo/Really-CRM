Overall: Core business logic is genuinely well-written — propertyMatch.ts is pure, deterministic, and easy to test; API routes validate input and scope every query by realtor_id. The health problems are not the algorithms — they are (1) stale documentation left behind by a recent Claude→local refactor, (2) machine-generated comment bloat from a committed LLM commenting script, and (3) data access hard-wired into UI components, which blocks unit testing. No test suite exists. Nothing here is an emergency; all of it is cheap to fix.

2 · Findings

Critical Stale docs: routes & a whole directory still claim to use Claude

app/api/property-match/route.ts:7-25 · lib/claude/propertyMatch.ts (dir name) · CLAUDE.md

Commit 0b50319 replaced the Claude matcher with a local algorithm. The docs never followed:

  • Route JSDoc (lines 7-23) still reads “orchestrates two sequential Claude API calls”, “cap Claude API spend”, and “Returns 502 if either Claude call fails.” None of it is true — there is no Claude call. Then lines 24-25 repeat the same summary as inline comments.
  • The module lives in lib/claude/ yet imports no AI SDK. @anthropic-ai/sdk is gone from package.json; grep finds zero anthropic references in app/components/lib.
  • CLAUDE.md (root + workspace) still lists ANTHROPIC_API_KEY as a required env var. It is dead.

Fix: rename lib/claude/ → lib/matching/, rewrite the route header to describe the local flow, drop ANTHROPIC_API_KEY from docs/env examples.

Critical AI-slop generator committed to the repo — the source of the comment bloat

scripts/qwen-comment.mjs (107 lines, zero inbound references)

This script pipes source files through a local Qwen model to auto-insert comments. It explains the uniform, over-formal JSDoc on trivial helpers throughout lib/. Examples of the resulting redundancy:

  • rateLimit.ts: a 13-line JSDoc block documents a 10-line function — the doc is longer than the code and repeats the one-line file header.
  • sendFollowUpEmail.ts:47: a comment restates the RESEND_FROM_EMAIL requirement already stated in the JSDoc two lines above.
  • propertyMatch.ts: every one-line private helper carries a full /** … */ banner.

Fix: delete scripts/qwen-comment.mjs (nothing imports it) and strip machine JSDoc from private single-line helpers — keep comments that explain why (the good ones on the scoring weights and the watch() caveat).

Critical Data access wired straight into UI — untestable, tightly coupled

12 client components import @/lib/supabase/client; 18 raw .from('…') calls live in components/

Components like ClientForm, the client tabs, PipelineBoard, FollowUpForm, and ProfileForm build queries, mutate rows, and render — all in one file. There is no data layer to mock, so none of this logic is unit-testable without a live Supabase. Business rules (validation, status transitions) sit next to JSX.

Fix: extract a thin lib/data/* repository per entity (getClients, upsertClient, …). Components call functions; tests mock the module. This also centralizes the realtor_id scoping now copy-pasted per query.

Warning Duplicated escapeHtml (DRY / coupling by copy)

lib/resend/sendClientEmail.ts:8-15 ≡ lib/resend/sendFollowUpEmail.ts:7-14

The identical 5-replace HTML escaper is defined in both mailer files. Two copies drift; a fix to one (e.g. escaping backticks) silently misses the other.

Fix: move to lib/html.ts (or lib/resend/escape.ts) and import in both. Consider a shared renderEmailShell() too — both files hand-roll the same <div>…<hr>…Really CRM</p> footer.

Warning Rate limiter is a module-global Map — hard to test & wrong on serverless

lib/rateLimit.ts:2

State lives in a top-level Map that no test can reset between cases, and each Vercel lambda instance keeps its own copy — the “10/min” limit is really “10/min per warm instance.” The file’s own comment admits this.

Fix: for testability, accept an injectable store or expose a reset(); for correctness under load, move to Upstash Redis as the comment already advises.

Warning ClientForm calls watch('sale_type') inside .map()

components/clients/ClientForm.tsx:271 (ESLint: react-hooks/incompatible-library, React Compiler skips memoizing the component)

Calling watch() inside a render-loop subscribes on every iteration and defeats the React Compiler for the whole component. Hoist one const saleType = watch('sale_type') above the .map().

Info Stale generated artifacts in the working tree

ruvector.db (1.5 MB) · .audit/ · tsconfig.tsbuildinfo · landing/

All correctly .gitignored (verified: none are tracked), so no repo bloat — but they clutter the tree and ruvector.db is a 1.5 MB binary from tooling unrelated to the app. Safe to delete locally if the ruflo/codegraph tooling isn’t in active use.

Info Minor: unused destructure + shallow-ish wrappers

lib/claude/propertyMatch.ts:268

_score flagged unused — it’s an intentional discard in .map(({ score: _score, ...rest }) => rest); harmless, silence with an eslint-disable or drop the alias. Otherwise no genuinely shallow modules were found: rateLimit, uploadFile, and the supabase helpers each carry real logic proportional to their surface.
